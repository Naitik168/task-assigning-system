# AI Usage

The brief allows AI tools as long as the candidate understands and can explain the code. This file records how AI was used.

## Tools used

- **Claude (Anthropic)**, via the Claude app in agentic mode. It had a sandboxed Linux workspace and could run `cargo`, `npm`, PostgreSQL, Redis and a headless browser.

## How the work was split

| Phase                                         | Who decided                                                                                                            | What the AI produced                                   |
| --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| Requirements analysis and implementation plan | Candidate reviewed and approved                                                                                        | A phased plan mapped to every requirement in the brief |
| Technology choices                            | **Candidate chose** each option (Axum; PostgreSQL + SQLx; Redis with an in-memory fallback; React + Vite + TypeScript) | A list of options with trade-offs                      |
| Containerisation requirement                  | **Candidate requested** Docker for all services plus a run guide                                                       | Dockerfiles, `docker-compose.yml`, `DOCKER_GUIDE.md`   |
| Backend, frontend, tests, scripts, docs       | Generated by AI, then reviewed by the candidate                                                                        | All source in this repository                          |

## How the output was verified (by running it, not by inspection only)

- `cargo fmt`, `cargo clippy --all-targets -- -D warnings`: clean.
- `cargo test`: 29 tests pass against real PostgreSQL 16, including the Redis-backed tests against a real Redis 7.
- `npm run typecheck`, `npm run build`, `npm test`: 12 tests pass.
- `scripts/validate.sh` ran the 11-step flow against the live API: all steps pass.
- A headless-browser script drove the real UI through the full flow against the live API. That run produced the screenshots in `docs/screenshots/`.
- `docker compose config` validated the Compose file. The images could not be pulled inside the AI's sandbox, because its network blocks Docker Hub. **The first full `docker compose up --build` was run by the candidate locally.**

## Issues the AI caught and fixed during development

- **React StrictMode** runs mount effects twice in development. That would call `view-my-tasks` twice, so the first screen would already show `cache.hit = true`. `useAsyncData` now guards against the double initial load.
- **The API client's token getter was configured in a parent `useEffect`.** Child effects run first, so the first authenticated request could go out without a token. It is now configured during render.
- **Expiry is evaluated with the database clock** (`expires_at <= now()` in SQL) instead of the application clock. Tests can backdate a challenge, and clock skew between containers can't matter.
